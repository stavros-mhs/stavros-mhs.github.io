# Task 1.3 - Set the theme before first paint

## Summary
The theme is now set before the page paints. An inline script in `<head>` resolves the theme from the saved choice, then the system setting, then dark, and sets `data-theme` on `<html>`. The CSS uses `data-theme` selectors, the `dark-mode` class is gone from `<body>`, and the toggle saves its choice under the `theme` key. Headless Chromium confirms four of the five cases and the toggle behaviour. Case 3 (no saved choice, system set to no preference) could not be run, because this Chromium reports `prefers-color-scheme: light` even when asked for no preference. The head script's logic for that case passes a Node simulation, which is not a browser test. The outcome is Partial because one browser case is unrun.

## Output
- `index.html`: an inline theme script in `<head>`, before the stylesheet link. `<body>` has no class. The end-of-body script only syncs the toggle on load and saves changes on the `change` event.
- `style.css`: `:root, :root[data-theme="dark"]` holds the dark tokens. `:root[data-theme="light"]` holds the light tokens. The `body:not(.dark-mode)` block is removed. No other rule changed.
- `/home/stavros-mhs/Projects/site-tools/contrast_check.py`: its `THEMES` list uses the new selectors. It is outside the repository and not committed.
- Branch: `fix/theme-flash`. Commit `3d2d52a`, `fix: set theme before first paint`.
- No other files changed.
- Test tooling, outside the repository and not committed: `/home/stavros-mhs/Projects/site-tools/theme_check.mjs` (Playwright, headless Chromium), installed in `/home/stavros-mhs/Projects/site-tools`.

- **Case 3 is untested in a browser.** Headless Chromium cannot emulate "no preference", so this case is covered only by the Node simulation. The logic is a single comparison, and the simulation tested it directly. Options: accept the simulation as the check, or test case 3 in a browser that can report no preference.
- **User decision:** accept case 3 on the Node simulation, and do not test it in another browser.
- **The first-paint check is indirect.** The `theme_check.mjs` probe confirms that `data-theme` is set before `<body>` is inserted into the document. It does not capture painted pixels, so "no dark frame" rests on that ordering, not on a screenshot.
