## Important Findings
1. **Queue removed (correction 3, `fa95d7d`).** The Task's rules are superseded: items no longer play one at a time in page order, and a step no longer waits for the previous step's `transitionend`. Items below the fold no longer wait behind the items before them. The fallback timer that only existed to recover from a stalled queue is gone too.
2. **Fix to Task 1.1 (on `main`, not merged).** In `3392d3b`, loading in minimal mode and then turning Animations on made every heading `visibility: hidden` for good, because nothing revealed it. I confirmed this on that code before changing anything. The fix is the `reveal-skipped` marker: the reveal script sets it on `<html>` when the page loads in minimal mode, and the hidden states are scoped to `:not(.reveal-skipped)`. Task 1.1 needs this fix.
3. **Task 1.1 finding 1 closed.** Headings wait at `opacity: 0`, not `visibility: hidden`. All five are in the accessibility tree before any scrolling.
4. **Behaviour beyond the spec:**
   - Leaving animated mode marks every item as shown and disconnects the observer. Switching back then hides nothing, and nothing replays.
   - The rules end at `transform: none`, not `scaleX(1)`. Chrome treats the two as different values, and `scaleX(1)` started an invisible transition on every rule each time the mode switched back.
   - The rules draw from the left (`transform-origin: left center`).
   - Body text is split into words, which are grouped by line. The grouping is measured at page load, so resizing the window before the reveal finishes can change the grouping. The text stays visible in full.
   - The Contact list items stagger like the other lists. The Task had the Contact list as one block.
   - If the reveal script throws after the fonts are ready, a catch reveals every item, so nothing stays hidden.
5. **Observer lead.** The Task's observer settings are unchanged: threshold 0.2, `rootMargin: 0px 0px -10% 0px`. A section starts once 20% of its height is above the bottom 10% of the screen. A larger bottom margin would start sections earlier, which may suit the "catch up" feel better. I have not changed it.
6. **Rules are still 400 ms, not matched to the headings.** The User asked only for headings and section content to match. The rules already matched the 400 ms reveal, so I left them alone.
7. **400 ms reading.** I read "up the animation speed to 400 ms" as a longer reveal. If the User meant faster, the constants and CSS durations need changing back.
8. **Frame timing.** Event times are quantised to about 17 ms. Measured durations are within one frame of the set values.
