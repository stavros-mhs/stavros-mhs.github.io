## Important Findings
1. **Branch base.** `AGENTS.md` says to cut a branch from `main` when a Task Prompt creates one. Task 1.4 said `feat/section-motion`. I asked the User. They chose to merge `feat/section-motion` into `main` first, and they did the merge. This branch is cut from `main` at `28810a8`, the same content.
2. **Focus after a link (added, not in the Task).** Following a panel link closes the panel. The `#skills` jump then moves focus off the burger in Chromium, so the link's handler sets focus on the burger in a 0 ms timeout after the jump. Without the timeout, focus was on `body` after following a link, which the Task's focus rule does not cover. The Manager should confirm this choice.
3. **Motion choices the Task left open.** The Task gave the 80 ms stagger and the `ls -l` command, and I chose the rest:
   - Letters start 60 ms apart and each fades in over 60 ms.
   - The command text is `ls -l`, with no `$` prompt.
   - The first listing line starts 300 ms after the command, when the five letters have typed.
   - Each line fades in over 250 ms.
   The 80 ms is measured start to start. Each open replays the sequence. If the User wants a different pace, the values are `TYPE_MS`, `LINE_MS` and the `0.06s` and `0.25s` in `style.css`.
4. **Panel text size.** The listing is 0.75rem (12px). At 0.8rem the longest line (47 characters, 376px) was 18px wider than the 358px panel at 390px, and the list scrolled sideways inside the panel. At 0.75rem the line is 329px, which fits the 374px panel width at 390px and the 344px width at 360px. The list runs to the panel's right edge, so the text stays aligned with the navbar.
5. **Hover (partly outside the Task).** The two new hover rules are inside `@media (hover: hover)`: `.nav-burger:hover` and `.nav-container a:hover`. The site-wide `a:hover` rule was already outside it, and I left it as it was. The panel links use that rule, so on a touch device a tapped link keeps its underline until the panel closes. The Manager should decide whether to move the site-wide rule.
6. **Without JavaScript, 390px.** The names fit on one line, and the toggle wraps below them (toggle top 60px, names top 16px). There is no sideways scroll.
7. **Phone layout with JavaScript.** The burger sits on the left and the Animations toggle on the right of the navbar. The names are hidden.
8. **Burger name.** The burger's accessible name is `Menu`, which is my choice. The Task asked for an accessible name but did not give one.
9. **Intro line length (carried from follow-up 01).** `qa_matrix.mjs` reports 24 characters per line over 14 lines for the intro at 390px, below its 45 to 90 target. This Task does not change the intro. The Manager should decide whether it needs a Task.
10. **Problems fixed during the Task.** The first full run failed in two places: the link focus (item 2) and the 18px listing overflow at 390px (item 4). Both were fixed, and the full run was repeated after each fix. The final run passed all 20 cells.
