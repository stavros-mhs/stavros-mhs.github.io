## Important Findings
1. **Accessibility trade-off in animated mode (needs a decision).** The Task requires `visibility: hidden` on a heading that is waiting to start. That also removes the heading and its visually hidden copy from the accessibility tree. Verified: "Hobbies" and "Contact Info" are not exposed until they scroll into view, in animated mode only. The `visibility: visible` on `.sr-only` that I first added did not fix this, so I removed it. Options for the Manager or User: keep the Task as written, or hide waiting headings with a method that keeps them in the tree (for example, `opacity: 0` on the letters only).
2. **Added rule for minimal mode (a deviation, small).** The Task says the minimal-mode transition block comes later. In testing, switching from animated to minimal replayed the stagger. The waiting letters kept their inline `transition-delay`, so Chrome ran zero-duration transitions that flipped each letter at its delay. Measured before the rule: 48 extra `transitionrun` events on switching to minimal and 36 more on switching back, and "Contact Info" letters flipped one by one between 148 and 565 ms after the click. After the rule: 0 events on switching to minimal. I added this rule to `style.css`:
   ```css
   html:not([data-motion="animated"]) .letter { transition: none; }
   ```
   The inline delays are unchanged, as the Task specifies. This rule only disables transitions. The later minimal-mode block should not conflict with it, but the Manager should confirm.
3. **Hidden state before the split (a choice).** The Task says a waiting heading has `visibility: hidden`. I applied the hidden state to every h1 and h2 in animated mode from page load, not only after the split. Without this, the h1 would show as plain text for a moment before the font loads and the split runs, and then vanish. Headings the split fails on are shown at once.
4. **Observer reuse for Task 1.2 (for the Manager).** The observer settings are in the constant `REVEAL_OBSERVER_OPTIONS`, but the observer instance is local to the font callback in the same script. Task 1.2 will need to edit that script to reuse the observer, not just the constant.
5. **Failure fallback.** If the script throws after the font is ready, a catch adds `is-revealed` to every h1 and h2, so no heading stays hidden. This is a choice beyond the Task's per-heading rule.
6. **Commit trailers.** The Task and `AGENTS.md` say no trailer lines. The session's attribution note asks for a `Co-Authored-By` line. I followed the Task and `AGENTS.md`.
