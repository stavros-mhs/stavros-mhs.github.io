# Task 3.7 - The landing terminal sits at the same height as on other pages

## Summary
The landing's terminal now has the same top as the terminal on every folder and file page: 72.0px on desktop (601px and wider) and 156.0px on phones, at every height tested. Its top does not move through the landing animation or while a folder opens in place. The fix is one rule in `style.css`: the landing no longer centres the terminal vertically. Folder and file pages are untouched. One consequence follows: a file page no longer has a move to make, because the terminal already sits at its final top. That changes what `md-test.mjs` can measure, and is in Important Findings. All other checks give the same results as in Task 3.4.

## Output
- Branch `feat/terminal-top`, one commit on top of `fc727e8`: `8a6736a fix: start the landing terminal at the top like every other page`. It changes `style.css` only (5 insertions, 10 deletions), no trailer lines, not pushed. The worktree is clean.

The `.landing.is-top { justify-content: flex-start; }` rule is removed, since it is now what every landing does. ## Important Findings
- **The file page's move is now a no-op, and still takes 400 ms.** `moveTo` measures the terminal's top before and after adding `is-top`; both are the same, so the transform is `translateY(0)`, nothing animates, and no `transitionend` fires. The code that schedules the markdown still waits `MOVE_MS` (400 ms) after the 300 ms pause, so there is a 700 ms gap after the command is typed with nothing moving. This follows from the Task's own rule (the terminal is at the same top everywhere). I did not remove the move or the wait, because the Rules say not to change animations unless the Task says so. The User or the Manager may want to remove `moveTo`, the `term-move` styles and the 400 ms wait in a follow-up, and, if so, to shorten the gap.
- **The `is-top` class is dead.** The script still toggles it and nothing styles it. It can go in a cleanup.
- **The landing box is as tall as its final output from the first frame**, so the bottom edge does not grow during the animation, only the visible lines do. That is how the landing already worked.
- **The landing's `min-height: 100vh` is kept**, so the noscript tree is still below the fold, and a short page still scrolls only as it did.
- `tools/` is untracked in the root checkout, as before.
