# Task 3.9 - A smooth clear, and a box that follows its content

## Summary
The clear sequence is reworked. The text, markdown and footnote fade out together inside the box over 250 ms, and the box keeps whatever height its content has. When the fade ends the old content goes and the box resizes to the empty box (its padding plus one prompt line, 74.0px on desktop and 62.7px on phones) over about 285 ms, ease-out. The current prompt is in the page at once, the `cd` types, the new prompt comes in at once, and then the rows come in one by one: each fades in over 250 ms while the box grows with it. The box's height is never fixed or held: the fixed-height lock (`holdHeight()` and `releaseHeight()`) is gone. After every move the box goes back to its natural height, so a page is the same size on every arrival of the same kind. Opening and closing a folder in place resizes the box smoothly too. The new `box-check.mjs` samples every animation frame: 126 passed and 0 failed at 1280px and 133 and 0 at 390px, in both themes, against 12 failures per width on the old code. All other checks give the same results as before, apart from the checks that measured the old hold, which are replaced.

## Important Findings
- **Fixed `height`, not `overflow-x: auto`.** The Task said to restore `overflow-x: auto` when the transition ends. The box has no `overflow` set in the stylesheet, so I remove the class and the inline height instead; the box is then as it was before.
- **The cause of the spill was reproduced but not fully explained.** The fixed height was in force and the old page's last line sat outside the box for the whole fade-out; why the held height was 48px less than the content in that case I did not isolate. The new design has no held height, so that question is closed in practice.
- **A click arrival and a typed arrival of the same page differ by the `cd` line** (34px, or 30.7px on phones). That follows from "no `cd` on Back and typed addresses". The root reached by a click is also different from the landing (the `whoami` lines).
- **A typed line that wraps on a phone grows the box at once** by a line, since typing is not an animated step. The box is not held then, so it follows.
- **Instant growth for prompts.** The new prompt line comes in at once with no height transition, since the Task says prompts appear at once; only rows, the prompt after the tree and an error's message and prompt grow the box smoothly.
- **Scrolled pages** go to the top at the moment the old content is removed, as before. Not re-measured separately beyond `sequence-check`, which still passes its scroll checks at the new prompt.
- `tools/` is untracked in the root checkout, as before.
