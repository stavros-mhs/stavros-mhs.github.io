## Important Findings
1. **Prompt colour and size (needs your decision).** The Task sets `~$` in `--accent`. At normal size the accent is 3.73:1 on the surface in dark and 3.31:1 in light, which fails the 4.5:1 for normal text. I set the prompt at 24px, which counts as large text, where 3:1 is the requirement, and both values pass. The prompt is larger than the text beside it, and the look may not be what you want. Options: keep 24px, or use a colour that passes 4.5:1 at normal size.
2. **Navbar transition in minimal mode (needs your decision).** The Task asks for `transitionDuration` 0s on the navbar in minimal mode. The navbar already has `transition: background 0.5s`, which is the theme colour change. `AGENTS.md` says existing colour transitions stay as they are, so I kept it. Removing it in minimal mode would make the theme change instant there. The output lines and the terminal have 0s.
3. **Timeline choices the Task left open.** The Task gave the steps and the times, and I chose these:
   - The fade is linear over 500 ms. The navbar drop is ease-out over 500 ms.
   - The typing covers the prompt as well as the command: `~$ whoami` is 9 characters and `~$ ls -l` is 8.
   - The navbar drops once the last output line has fully faded in (3483 ms), not when its start (3240 ms) arrives. "Has printed" is read as "is visible".
   - The blank line in the output is one of the seven timed lines, so the output takes 120 ms per line including the blank.
4. **Terminal names are links.** The Task gives the directory names the link colour. I made them links to the same routes as the navbar, so colour and behaviour match. `~/` and `4 directories` are plain text.
5. **Phone panel.** The panel holds the seven tree lines from the output, with `~/` and `4 directories` as well as the four links. It no longer types or fades. The Task 1.4 typing and the `ls -l` header were removed, since the command is in the terminal. Its font is 0.9rem.
6. **Hidden until the script runs.** In animated mode the terminal and the navbar start at opacity 0 in CSS, so no static text shows before the timeline is set (a 40 ms flash showed before this fix). A `try` around the script sets `term-failed` if it throws, and then everything shows. Leaving animated mode removes `term-live` and stops the timeline. Switching back does not replay it.
7. **Centring depends on the navbar height.** The landing's height is the viewport less 208px on desktop (navbar 72px, with its margins) and less 168px on phones (navbar 68px). Measured at 1280x900 and 390x900, the terminal is centred. Without JavaScript on a phone, the names and the toggle wrap, so the terminal's centre is at 487.5px rather than 450px. That is a noted limit.
8. **Old section visible in the first screen.** At 1280x900 the top of the old `whoami` heading shows at the bottom edge of the first screen, just below the terminal. The Task keeps the old sections below the terminal, so I did not move them.
9. **Focus rings.** The navbar and terminal links have a 2px `--focus` ring with 3px offset. The Task required it. The site-wide `a:hover` rule is still outside `@media (hover: hover)`, as in follow-up 01.
