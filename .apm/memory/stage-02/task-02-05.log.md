## Important Findings
1. **The footer's light-mode contrast is below the normal-text rule.** The footer is normal text, not a directory name. In light mode `--dir` on the page background is 3.82:1. It passes the 3.31:1 target, but the rule that exempts directory names does not cover the footer, so it needs 4.5:1. The Task says not to change the colour, and I did not. The Manager decides whether the footer is a directory name, uses a darker token, or gets a different colour.
2. **The footer can sit under the Animations switch on a 360px phone at first load.** On `#/user/WHOAMI.md` at 360px wide, the footer's text overlaps the switch's "On" label when the page is at scroll 0, in both 360×780 and 360×844 viewports. Scrolled to the end, the footer clears the switch. At 390px wide it does not overlap. The switch is fixed to the bottom of the screen, and the Task says not to change it. Fixing this would mean moving the footer, changing the page's spacing, or changing the switch. The Manager decides. The Task 2.4 phone check did not cover footer text.
3. **Interpretation of "the tree terminal fades out".** The tree terminal and the cat terminal are the same box, `#terminal`, inside a wrapper, `#term-stage`. The box fades out and back as one piece, so it looks like one terminal changing. The Task says the cat terminal has the same surface box as the other terminals, so this matches it.
4. **The first markdown block starts one frame before the move's end event.** The blocks are scheduled at the move's end time, and the transition event fires a frame after the style change. This is within the one-frame tolerance the Task allows.
5. **The move keeps the layout still.** The terminal is moved with a transform from its centred position to its top position, both measured. The page's layout changes to the top position at once. The markdown is hidden until the move has ended, so the centred terminal is not pushed up by content below it.
6. **The swap waits for the fade's end event.** An earlier version swapped on a timer. The timer fired while the fade-out was still running, which cancelled the fade. The swap now waits for the fade's `transitionend`, with the timer only as a fallback of 350 ms.
7. **Typing takes about 4 s for the full prompt.** The Task asks for the whole prompt to type at the Task 2.1 pace. A 32-character line at 90 to 170 ms per character takes about 4 s (518 ms to 4539 ms in the final run). This is what the Task specifies.
