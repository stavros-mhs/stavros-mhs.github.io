# Task 2.2 - Navigate the terminal with cd, cd .. and markdown subpages

Original Task 2.1 landing: `.apm/memory/stage-02/task-02-01.log.md`, with follow-ups up to `task-02-01.followup-05.log.md`. Base commit: `0f17621` (`main`).

## Summary
The terminal navigates by a click on a folder or file, by the navbar, by `cd ..`, and by the address after `#` (back, forward and a typed address). The landing from Task 2.1 keeps its timeline. Every listing and file of the Task is reachable, and each file's rendered content matches its text. The behaviour changed twice after the first delivery, at the User's direction. The User has reviewed the final state and accepted it, so the status is Success. Where the delivered behaviour differs from the Task Prompt, the differences are below under Important Findings.

Final behaviour:
- **Landing (`#/`).** Animated mode types `whoami` and `tree`, and the tree fades in. The title is `/`, and the prompt is `~$`.
- **Folder in the tree.** A click opens or closes the folder in place. Its rows appear under it with the branch glyphs. The count line changes as each row appears or closes. A click also makes the folder the current path: the title, the prompt and the address change to it.
- **Folder page (navbar, back, forward, a typed address, or `cd ..` from a file).** The terminal sits at the top, just below the navbar. It types `tree <folder>/` at `~$`, prints the folder's tree with the same in-place expansion and live count, and then shows `cd ..` and a prompt with the folder's path. `cd ..` goes to the parent folder's page, or to the landing for a top-level folder.
- **File page (a click on a file, back, forward, or a direct load).** The terminal sits at the top, types `cat <name>` at the file's folder prompt, then prints `cd ..` and a new prompt. The file's markdown is printed below the terminal. Each block starts 120 ms after the one before it. `cd ..` returns to the file's folder page.
- **Unknown route.** The terminal types `cd <path>` and prints `cd: no such file or directory`, with a `cd ..` back to the current folder.
- **Title.** The tab shows the path only: `/`, `/projects`, `/projects/aralloc/BRIEF.md`.
- **Address.** The hash shows the same path, for example `#/projects/aralloc/BRIEF.md`.
- **Minimal mode.** Each change shows at once. There is no typing, fade or cursor, and all transitions are `0s`.
- **No JavaScript.** The landing stays as it is. A `<noscript>` tree sits below it, with six raw-file links and the `source/` links to the repositories.

## Important Findings
1. **The User changed the behaviour the Task Prompt specified, and the User has accepted the result.** The Task said a directory click types `cd` and prints that directory's tree, the navbar does the same as `cd`, and a file's subpage prints its content in the terminal. The delivered behaviour, at the User's direction, is:
   - a directory opens or closes in place in the tree, with no typed command and no printed listing;
   - the command history is gone, and the terminal shows one page at a time;
   - the navbar opens a folder page, which types `tree <folder>/`;
   - a file's markdown prints below the terminal, not inside it.
   The Manager should decide whether to record these as the Task's amended spec, or to issue a follow-up that brings them back to the Task Prompt.
2. **Choices I made where the Task and the User left room.**
   - A click on an open folder closes it, and the folder becomes the current path either way.
   - The `cd ..` line on a file page sits in the terminal, under `cat`, above the prompt.
   - Folder and file pages start the terminal at the top, below the navbar, and the home page stays centred.
   - Going home from another page types `tree` and does not replay the whole landing.
   - The count counts `source/` as a directory, as the Task's listings do.
   - In the first delivery, a `cd ..` that goes up a level prints the parent's listing. The later pages keep that behaviour, now as a page.
3. **A bug from Task 2.1 is fixed on this branch.** Switching from minimal to animated mode at runtime left the terminal and navbar hidden. The mode switch now adds `term-live`, so they show again. This changes the landing only in that case.
4. **The landing's centring shifts the rows.** The landing is vertically centred, so opening a folder on the home page moves its row up by half the height added. Opening `projects/` moves it up 34 px. The User has seen this and accepted it.
5. **The noscript tree is built from the listings, not from the Spec.** I did not read the Spec, per the Rules. The Manager should check the tree against it. The counts follow the listings: `8 directories, 6 files`, with `source/` counted as a directory.
