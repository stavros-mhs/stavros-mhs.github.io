## Validation
Method for `prompt-timing.mjs`: Playwright, headless Chromium, animated mode, localhost:8000 serving the worktree. A `MutationObserver` on the body (childList, characterData and style or class attributes) samples every `.term-line` that holds a `.term-prompt`, with `performance.now()`, on every DOM change. For each line it records when the prompt's text grows, and when the command text after it grows. Lines that were on the page before the action are left out. A prompt fails if its characters take more than 20 ms, about one frame, to appear in full. It also fails if the command's gaps leave 70 to 190 ms (one frame of tolerance around 90 to 170), or if the first command character comes outside that range after the prompt on file lines. The observer's callback runs after the DOM change, so each time can be a little late, but one action's changes share one callback.

## Important Findings
- **The fade is separate from typing.** Lines that appear after a command (the tree rows and the prompt after the tree, for example) are inserted with `opacity: 0` and revealed with the 250 ms opacity fade. The prompt's characters are in the page from the start in one piece. The check measures when the prompt's text is complete, not when its fade ends. I left the fade alone, as the Task said to keep lines that already printed at once.
- **The command's first character** now comes one typing interval (90 to 170 ms) after the prompt, as asked. Before, it came one interval after the space.
- **Total typing time on a file page is shorter**, because the prompt and its space no longer take time. For `~/projects/aralloc$ cat BRIEF.md` that is 20 characters less to type. The move and the markdown follow 300 ms after the last command character, as before, so they start earlier by that amount.
